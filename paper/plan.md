# AIMLL Workshop 后续路线（2026-11-05）

2026-11-06 稿件标题为 **GrantBind: Task-Scoped Tool Execution Mediation against Indirect Prompt Injection**。引言按背景、挑战和方法展开。结果章单列 Qwen3.5-Flash 配置图，并收录 Qwen3.8 v3.7 攻击组与 Qwen3.5 混合 clean 组的离线报告截图。跨论文方法对比和组件消融已在正文预留，采用固定模型、版本和任务键的配对口径。

以现有 AgentDojo 实验写清 GrantBind 的适用边界。任务级授权与逐动作审计要求模型稳定地遵守输出协议，并判断当前动作是否有充分依据。Qwen3.7-Flash 配置的任务完成率上升，原生攻击命中减少。DeepSeek-Flash 配置的任务完成率小幅下降，原生攻击命中减少。Qwen3.8-Flash 的 v3.7 固定网格上任务完成率上升，原生命中总数相同，但命中键不同。Qwen3.5-Flash 同模型配置的任务损失作为限制案例保留在正文，分场景与诊断结果放入附录。

## 1. 证据与版本

论文主实验使用 GrantBind v3.7。历史 v3.6.3 结果使用同一框架配置，保留原运行标识。v3.8 作为附录中的兼容尝试。

| 配置 | 有效配对键 | 原生 TSR，baseline → GrantBind | 原生攻击命中数，baseline → GrantBind | 论文位置 |
| --- | ---: | ---: | ---: | --- |
| Qwen3.7-Flash / v3.6.3 | 1,943 | 73.3% → 79.3% | 438 → 0 | 主结果 |
| DeepSeek-Flash / v3.6.3 | 1,836 | 83.6% → 82.4% | 38 → 5 | 主结果，低基线 ASR 对照 |
| Qwen3.8-Flash / v3.7 | 108 | 84.3% → 90.7% | 2 → 2，命中键互不重叠 | 主结果，单列固定网格 |
| Qwen3.5-Flash / v3.7 | 2,139 | 84.4% → 54.9% | 221 → 2 | 正文保留摘要，完整结果进附录 |

Qwen3.8-Flash 的两臂使用同一未筛选网格，四场景各 27 个键。clean 两臂均为 83/97，各有 7 个任务向相反方向翻转。稿件仅纳入该模型的 v3.7 对照。

Qwen3.5-Flash 的 clean 成功数从 90/97 降到 53/97，四个场景均下降。逐键结果显示，任务失败涉及 L2 协议、L3 阻断，以及规划和交付遗漏。使用 Qwen3.5 做主模型、Qwen3.7 做审计器的混合组成功 82/97，较同模型 v3.7 改善 29 键，较原生基线少 8 个成功任务。该组同时采用 v3.8 的 L2 输出协议，结果描述这套组合在 clean 条件下的表现。独立估计审计器作用需要固定主模型、L2 协议与任务键。[v3.7 分析](../analysis/v3.7.md) · [论文数字源](fig/paper_numbers.json)

### v3.8 的定位

v3.8 是 Qwen3.5-Flash 的 L2 兼容尝试。定向开发集上，初版适配将 L2 协议错误从 15/64 降到 2/64，任务成功从 v3.7 的 4/64 增至 19/64，同键原生基线为 54/64。最终交付快照单独验证了 16 个 clean 键，L2 协议错误为 0/16，任务成功为 3/16，其中 5 个键仍有 L3 abstain。审计提示的试验未见净收益并已撤回。各快照和子集分别报告，保留实际运行标识和 wire 协议。

论文将 v3.8 的定向同模型结果作为局部兼容诊断，和 97 键混合 clean 分开报告。定向样本来自此前失败键，19/64 仅用于说明该开发集上的变化。根据已有尝试，继续针对该模型调协议和提示的预期边际收益较低，此方向停止迭代。[v3.8 验证记录](../analysis/v3.8.md)

## 3. 附录验收

1. **v3.7 全量结果。** 汇总 2,139 个共同有效攻击键与 97 个 clean 用户任务，列出四场景 TSR、原生 ASR、分母与记录错误。攻击批已知总 token 为 45.29M → 48.66M，包含生成、L2 与审计，基线另有未知用量。clean ASR 标为不适用。
2. **失败分析。** 报告 719 个退步键中 261 个 L2 编译失败与 344 个曾被阻断的键。分别展示协议错误、短且完整输入上的 abstain、未发起调用和执行后未完成。区分发生过阻断和确认的误拒。
3. **攻击命中。** 保留 v3.7 的两次原生攻击命中及其最终文本引用行为，注明原生判据与人工解释各自的口径。
4. **v3.8 尝试。** 分开报告选定开发键与完整混合 clean。以运行 manifest 的模型角色和 wire 字段确认混合组身份。
5. **提交形式。** 优先按会务对附录及补充材料的规则安排页数与入口。如果采用独立附件，正文保留核心负结果及其数据定位。
