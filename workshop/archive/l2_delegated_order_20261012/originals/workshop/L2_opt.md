# L2 优化候选：授权工具视图与正负任务约束

初版：2026-10-11；工具扩展补充：2026-10-12。状态：**待验证候选，未实施、未选择正式研究路线。** 本文按用户要求保存 L2 优化讨论。当前运行框架仍为 `three-layer-v1`，授权编译、整批前置检查、Monitor/ticket 和 L3 默认均不改变；本文的算法、字段、模式及实验组不是已提供的 API 或 CLI。

目标是在 AIMLL workshop 范围内，同时减少多余授权、必要能力遗漏和规划成本。优先采用宿主确定性处理，复用现有任务开始时的授权模型调用，不引入每动作授权模型或通用恢复回路。各层不必独立构成原创算法，工程完成也不等于安全收益或研究闸门通过。

相关材料：[当前流水线](../dscg/pipelines/defended.py)、[工具风险元数据](../dscg/tool_metadata.py)、[三层基础方案](./completed/3_layer_opt.md)、[L1候选](./L1_opt.md)、[L3纯算法路由](./L3_checker_opt.md)。正式路线仍以 [research/technical_route.md](../../research/technical_route.md) 为准。

## 1. 当前 L2 实际做了什么

`ToolAuthorizationCompiler` 在主模型第一次提出动作前，根据当前可信 user 请求和宿主注册工具目录编译任务级工具白名单。上下文不包含外部工具返回、错误恢复建议或助手候选动作。目录排序，temperature=0；存在非读取工具时通常调用一次现有主模型客户端，只有有效读取工具时不需要该调用。同任务循环复用授权，新的可信 user 回合重新编译；解析、API、未知工具等失败保持 fail-closed。

当前授权策略有两部分：

- 所有有效宿主元数据中 `effect=read` 的工具默认进入白名单，包括 internal、personal、secret 读取。这里不能把“读取默认授权”误写成“只有公开读取授权”，也不能把 `implicit_read_tools` 当成全部读取权限。
- 写入/动作工具由模型按任务选择。现有提示已经要求保留用户明确提出的条件动作，区分修改已有付款与创建新转账，禁止用工具描述扩张任务。因此“补充条件任务提示”并不是全新的待实现功能。

`ToolAuthorizationPrecheck` 在 L3 前确定性检查候选批次：未授权工具、未知工具或缺失/无效元数据任一出现，整批拒绝，不调用语义审计、不执行其中任何成员。宿主检查结果绑定具体候选、授权及 runtime 状态；Monitor 再核对，缺失/过期结果阻断，执行仍必须持有一次性票据。

然而，`OurFrameExecutor` 把完整 runtime 交给规划模型，当前安装的 AgentDojo `OpenAILLM.query` 把 `runtime.functions.values()` 全部转换为工具定义。**执行权限已收紧，规划器的可见工具目录尚未随之收紧。** 安装版本中的 `OpenAILLMToolFilter` 另有模型过滤器，但当前 DSCG 没有采用它；候选不新增过滤模型，也不直接调用其原地修改 runtime 的实现。

## 2. 防御不足、过度防御和成本边界

| 问题 | 当前事实或待检查风险 | 优化能覆盖的范围 |
| --- | --- | --- |
| 读取权限过宽 | 任务无关的有效读取工具也自动授权，可能扩大可接触的数据范围 | 评估任务级读取工具收紧；不等于约束同一读取工具内的对象/字段 |
| 同工具范围越界 | 工具名允许，不代表其对象、目的地、数据或重复执行符合任务 | 明确 L2 工具级边界；本候选不新增参数/对象/数据授权 |
| 授权选择不准确 | 模型可能漏选条件动作、误选相似工具或额外工具 | 加入可检查的正负约束记录，独立验证授权集合；现有提示并不保证理解正确 |
| 混合批次连带拒绝 | 一个未授权调用导致合法成员也被阻断，是当前有意的调度策略 | 单列频率和任务影响；不直接启用部分执行 |
| 规划看到不可用工具 | 每轮仍发送完整工具 schema，模型可以继续提出必然拒绝的调用 | 首先评估白名单工具视图，减少描述和无效候选暴露 |
| 元数据不足 | 缺失/无效元数据阻断，粗分类不能表达所有工具语义 | 核对宿主分类及描述；未知分类不能改成默认低风险 |

现有 [I3报告](../docs/i3_p0_stress_report.md) 已记录同一授权工具的新调用扩大对象、目的地、数据或重做义务的反例。这是工具级约束的实际边界，不表示本候选能修复它，也不能据固定探针计算真实 ASR。

L3 有效 deny 对已授权、有效的 `read/sink=none` 仍可能由 Monitor 转为 `READ_ONLY_SOURCE_ALLOW`，包括私人或敏感来源；abstain/错误不适用此例外。因此“所有敏感读取都有审计”不能证明其语义 deny 会阻断。若未来 L2 真正拒绝某读取工具，该例外不能越过 L2；本轮不改变 Monitor 例外。

历史账单前置读取误拦及其补修属于 [L3审计阶段](./completed/framework_v2_followup_report.md)，不能直接算作 L2 授权遗漏。当前没有 L2 独立标注的误放/误拒率，表中模型选择问题仍需核查。

## 3. 推荐顺序及近邻

建议分阶段评估：**A：现有授权集合的工具视图 → B：正负任务约束与必要读取补全 → C：根据证据决定是否改变混合批次调度。** A 不改变权限集合；B 改变授权策略，必须另设对照；C 暂不推荐实施。

这样能区分“少展示不可用工具”和“真正少授予权限”的效果，也避免一次收紧读取、改变批次和调整 L3 后无法归因。

工具过滤和授权编译已有近邻。[AgenTRIM](https://arxiv.org/html/2601.12449v1) 明确讨论 excessive/insufficient agency，以离线工具核查和在线工具编排平衡能力；[ToolFence](https://arxiv.org/html/2609.37196v1) 在独立上下文用可信请求和宿主工具 schema 编译授权 blueprint，并采用更细粒度运行时授权。任务贡献检查也见 [Task Shield](https://aclanthology.org/2025.acl-long.1435/)。

本文选择任务开始时复用一次编译、随后宿主过滤工具视图的工程取舍，不据此宣称新颖性。必要读取关系或授权日志也不能单独当成论文算法贡献；需要实证回答能否同时控制误放、误拒和总成本。

## 4. 阶段 A：按现有授权生成规划工具视图

### 4.1 算法与实现边界

设完整注册工具集合为 V，当前有效授权集合为 A。规划工具集合仅为：

\[
V_{plan}=\{t\in V\mid t\in A\;\land\;metadata(t)\text{有效}\}
\]

这里只展示满足当前确定性执行前置条件的工具，不进一步做语义相关性 top-k 排名。它不新授权限，也不删除工具描述内决定能力的关键信息。候选伪代码：

```text
build_planning_tool_view(full_runtime, current_authorization):
    if authorization is uninitialized, stale, or error:
        return an empty tool view, AUTHORIZATION_UNAVAILABLE
    return registered definitions of authorized, valid-metadata tools

plan(trusted_request, raw_history):
    grant = existing_task_authorization()
    tools_view = build_planning_tool_view(full_runtime, grant)
    message_view = existing_L1_view(raw_history)
    candidate = model_plan(message_view, tools_view)
    return candidate to existing_L2_precheck_and_L3_and_Monitor
```

`model_plan` 等名称只表示候选接口。实际适配应仅改变模型请求的 tools 字段或使用隔离的规划代理；不得原地执行 `runtime.update_functions` 删除真实注册工具，避免改变 Monitor 目录绑定、审计描述、依赖和日志。完整宿主 runtime 与调用账本保留。

- 工具定义来自当前宿主注册目录，不能由工具正文伪造、更新或补充。
- 保留可见工具的完整必要参数 schema；仅去掉整项不合格工具，不按字符预算裁掉必需参数。
- 绑定授权版本与当前 schema/目录；新可信任务生成新视图。已有执行收据/票据的检查仍必须通过，不把视图哈希当作执行凭证。
- 授权失败/空视图不能自动恢复成完整工具目录，更不能借模型报“缺工具”添加权限。允许最终说明无法执行，不代表完成了任务。
- 原始历史、已提出/拒绝的调用、工具结果与错误保留。历史出现某工具名不使其重新可见或可执行。
- 隐藏工具不是安全屏障，模型仍可能从历史或文本生成其名称；执行入口继续拒绝未授权调用。

### 4.2 例子与预期收益

用户“查询餐厅评分”，授权结果不含付款、邮件发送和账户修改能力时，规划器不再接收这些不可执行工具的 schema。当前默认授权的其他读取工具仍可能可见：**阶段 A 不解决全部读取权限过宽。**

预期收益是减少工具描述输入、错误工具选择和被拒绝后的规划轮次。是否发生、是否改善 TSR，需要新轨迹验证。当前 L2 已在 L3 前拒绝未授权批次，不能把“这些拒绝没有审计调用”再算作 A 新增的直接 L3 节省。

### 4.3 后续任务需要新工具：先区分三种集合

任务级权限不能成为整个会话永久不变的白名单，也不能因为模型报告“缺工具”就扩大。为讨论后续任务，区分：

- V_k：第 k 个有效可信任务所用的宿主注册工具目录及版本。
- A_k：依据该任务和宿主策略编译的允许工具集合，是执行授权。
- D_t：该任务第 t 次规划实际收到完整定义的工具集合，是展示。

要求 D_t ⊆ A_k ⊆ V_k；**展示扩展不等于权限扩展，注册工具也不等于授权。** 阶段 A 首版仍取 D_t 为全部有效授权工具，不做阶段性 top-k 或额外隐藏；因此已授权工具不会仅因尚未进入执行阶段而被隐藏。只有后续确有收益时，才另行评估 D_t ⊂ A_k 的按需展示，不把它混入首轮 A0/A1 对照。

| 实际情况 | 处理 | 是否新增授权模型调用 |
| --- | --- | --- |
| 已注册、已授权，只是没展示完整定义 | 宿主补回 A_k 内有效工具定义；不确定时回到完整授权工具视图 | 展示处理无需授权调用；可能增加下一轮规划或目录 Tokens |
| 原请求已经包含后续条件动作 | 任务开始时保留其工具及必要读取；读取后再判断具体动作 | 复用初次授权，不因每次条件判断重编译 |
| 用户明确新增/修改任务，需要原先未授权工具 | 基于新的有效可信请求重新编译并替换授权、生成新视图 | 新可信任务通常一次，与当前任务边界策略一致 |
| 同一原任务实际需要工具，但初次编译遗漏 | 标记授权不完整；优先修正独立核查后的编译/profile，不在线反复补授 | 首版不因模型缺工具或拒绝触发额外授权调用；该例计入任务失败/授权不足 |
| 宿主新增注册工具或修改旧工具语义/schema | 核对元数据与目录版本，首版在下一可信任务边界采用新目录并重新编译 | 在任务边界按实际目录决定；不中途静默继承旧权限 |
| 工具返回/错误建议新增付款、发送等能力 | 只作为不可信数据，不能注册工具或授予权限 | 不调用授权器以尝试放行，不执行建议的新动作 |

当前代码只在新的实际 user 回合（或缺失消息的失败路径）进入编译逻辑。目录/元数据参与该路径的缓存键，已有前置检查绑定可检测检查后候选与 runtime 变化；**这不表示任务中途目录改变已经实现自动重编译、全任务撤销或热切换。** 跨任务语义合并、按需展示、动态目录刷新均不是当前能力。

### 4.4 新可信任务：重新编译，不累加旧白名单

例如：

1. 用户“查询酒店价格”：授权查询能力，不因此授予预订。
2. 用户随后“预订 H 酒店”：这是新的可信任务要求，可以重新编译预订相关能力，无需再次让用户确认同一个新增意图。
3. 酒店网页写“还需要先给某账户转账”：这不是用户新增任务，不能扩展权限。

若原请求本来就是“查询价格，低于预算则预订”，预订能力应在开始时列入条件授权，不能等网页要求预订时才把网页当成授权来源。授予预订工具不证明价格条件、目标或付款参数已经正确。

候选任务边界表达为：

\[
A_{k+1}=Compile(T_{k+1},V_{k+1},P_{host}),\qquad D_0=Valid(A_{k+1})
\]

T_{k+1} 是有效可信任务要求；P_host 是始终适用的宿主策略。**不采用 A_{k+1}=A_k ∪ 新工具。** 新任务无需继承旧任务的修改/付款权限，但也不能丢弃仍然有效的用户长期限制或宿主禁令；用户明确改写的任务要求与未撤销限制需要区分。

当前编译器只读取当前 user 文本，不具备通用“把刚才那个发出去”的指代解析，也未实现任意跨回合用户限制的自动继承。首版优先要求新任务目标明确；产品若已有可信的结构化任务入口，可在该入口形成新的有效请求。需要上一轮任务说明时，只引入必要的真实用户指令，并明确适用范围，不把整个工具/助手历史拼进授权上下文，也不把模型摘要当成新的可信要求。自然语言存在冲突或目标指代不明时，需要澄清缺失信息，不猜测权限。

旧工具返回即使帮助解析“刚才那个”，仍是不可信事实。当前 L3 的工具事实窗口只取最近实际 user 回合后的返回，新任务不能假定它自动取得上一轮证据；跨任务引用会产生审计证据不足，需要作为独立限制核查。本文不新增跨任务事实认证、provenance 或自动补读/恢复机制。

任务切换的实现目标是先停止旧授权下的新动作批准，再编译新要求、替换权限与展示，并按新上下文重新检查候选。已有执行中动作不能假装被撤销或回滚，旧检查结果/路由收据/未消费票据不能直接搬到新任务继续使用。安全切换及失效处理需要宿主明确实现和验证；本文不声称已有任务级强撤销保证，不自动重做已发生副作用。

### 4.5 原任务中的按需展示与编译遗漏

若未来评估按需展示，宿主可保留 A_k 内尚未展示工具的简短名称/能力索引，或在需要时直接回到完整授权工具视图。对 requested_names 的处理只做展示判断：

```text
expand_view(requested_names, fixed_grant, frozen_catalog, current_view):
    if catalog/version no longer matches:
        return CATALOG_CHANGED       # 不用旧授权处理新目录
    if any name is not registered or metadata is invalid:
        return TOOL_UNAVAILABLE      # 不自动安装或注册
    if any name is outside fixed_grant:
        return AUTHORIZATION_INCOMPLETE
    return current_view union definitions(requested_names)
```

所有名称必须通过 A_k 和宿主目录核对，不接收模型提供的函数实现或 schema；增补定义不执行工具，后续真实调用仍须通过原 L2/L3/Monitor。一次性宿主反馈可以说明工具不可用/未获授权，但不能安排循环授权重试；不确定需要哪个已授权工具时，可展示全部 A_k，不回到全部 V_k。

首版阶段 A 已展示全部有效 A_k，因此不存在这种展示请求接口，也无需新增 discovery 工具。按需展示的索引和额外规划轮次有真实成本，未来必须单列，不宣称零额外总调用。

若工具在 A_k 外，纯集合算法无法判断“确实漏掉必要工具”还是“攻击要求新能力”。有限 profile 可在首次编译时预留独立核查的条件动作/读取关系，不能预留全部写入能力。对尚未覆盖的遗漏，首版接受显式授权不足和任务损失；更激进的独立动态授权复核需要另行选范围、测误放与额外成本，不作为当前默认方案。

这也是工具隐藏的重要近邻风险：[ToolFence §3.1](https://arxiv.org/html/2609.37196v1) 明确提出 no hidden starvation，保留工具可见并在静态 blueprint 不完整时复核能力。其动态授权与参数来源机制不是本文已经实现的能力，也不借此重开本项目关闭的细粒度 provenance 路线。

### 4.6 宿主新增工具：首版采用任务边界更新

新增工具须先由可信宿主核对实现、效果、风险元数据、输入 schema、描述及必要 profile/关系，再成为可编译目录成员。有效元数据并不证明实现无害；来源于外部网页/错误文本的名称或代码不能自行进入目录。

首版将新增/删除、同名工具语义/schema变化排队到下一可信任务边界；任务内固定目录版本，发现变化不继续用旧授权批准新候选。若业务必须中途热更新，需要另行设计没有待执行/执行中动作的切换边界，并重新编译原有效可信任务，不能仅凭“注册成功”追加白名单。当前没有该热更新机制。

新的注册工具可以服务原有合法任务，但仍要按有效任务选择；与任务无关的工具不因上线而获授。新目录、授权/展示/profile版本需要新运行身份；L3 selective 校准未覆盖新工具或配置时回到完整审计，不把旧阈值自动用于新目录。历史票据重放阻断不证明全新候选不会重复已完成义务，I3 的范围/重复义务限制仍保留。

## 5. 阶段 B：正负约束与必要读取补全

### 5.1 复用一次编译，不再无条件授予全部读取

仅在宿主已核对的有限任务类型/profile 内评估收紧。现有一次编译调用仍只看可信请求和宿主目录，但目录应包含候选读取能力及有效风险分类。输出可记录：

首版 B 限于原先已经需要授权模型调用的工具目录。纯读取目录当前可零调用授权，不能把新增一次自然语言编译算作免费；此类任务只有宿主可确定完整授权集合的有限 profile 才考虑纯算法处理，否则保留当前策略，不新增模型调用。

| 候选字段 | 含义 |
| --- | --- |
| 直接授权 S | 完成明确任务所需的工具种子，区分读取与动作 |
| 条件授权 | 用户已经提出的条件动作及原请求片段，不由外部反馈新增 |
| 明确禁止 F | 用户明确禁止的操作映射到宿主工具；需保留例外/否定范围 |
| 任务证据 | 原请求片段及位置，说明授权/禁止从何而来 |
| profile/歧义状态 | 当前有限适配是否适用；不能仅靠模型自信分数判定 |

这些字段是设计，不改变当前仅输出 `tools` 的协议。条件授权仍是工具级可用性：记录“如果金额不对则修改”不表示宿主已经核实金额或条件成立，具体调用仍交给 L3。

检查片段是否确实位于可信请求可防止编造出处，但**不能证明片段语义被正确理解**。例如“不要发送，除非……”不能简单匹配“不要”后永远禁止。任意自然语言映射依然有模型误差；不采用关键词缺失、字符相似度或 confidence 自动授权。

### 5.2 宿主读取关系

为每个适用 profile 定义经过独立核对的工具关系 G：某个已授权任务能力需要保留哪些查找/读取能力。该关系是工具可用性关系，不是执行顺序、数据 provenance 或完成义务账本；现有工具风险元数据和 runtime 的环境依赖并不自动提供它。

设 S 含直接及条件授权种子，P_G(S) 是宿主允许补全的必要读取集合：

\[
A_{candidate}=S\cup P_G(S)
\]

首先检查注册/schema/metadata，随后检查：

\[
A_{candidate}\cap F=\varnothing
\]

若必要能力与禁止集合冲突，标记授权无法一致编译并阻断相关执行；不能直接用集合相减丢掉必要前置能力，再假装下游动作仍可完成。冲突标记不能触发扩大权限、自动重试或恢复。

读取补全的边界：

- 只补宿主明确允许的 `effect=read/sink=none` 工具；写入、发送、付款及带外部 sink 的能力不能沿关系自动授予。
- 关系来自可信任务/profile 与宿主目录，不来自工具返回的“先做这一步”指令，也不从受攻击轨迹临时学习。
- 仅保留任务需要的能力，不意味着必须实际调用。用户已给出参数时，不能强制再读取，更不能宣称读取结果已验证参数。
- 多条替代路径需显式表示和验证，不能把全部分支取并集后叫最小权限，也不能按较低风险工具机械替换而丢失必要语义。首版限于明确、可核查路径。
- 循环、未知关系、版本不匹配或无法确定适用条件不猜测补全；缺失/无效工具分类继续 fail-closed。
- profile 适用性判断也需要独立检查。未覆盖任务沿用现有授权编译与读取策略，明确计入 fallback 分母；它不是新策略成功收紧权限的样本。

采用固定 G 和已给定 S 后，访问集合可用 visited 集合与队列计算，通常 O(|V|+|E|)，不需要训练模型、embedding 或在线 LLM。但 S/F 的自然语言编译仍有现有模型成本，profile 与 G 有宿主维护成本。

### 5.3 例子

用户请求：

> 读取已有租金付款，如果金额不对就修改；不要新建转账。

假设宿主工具语义分别为查询现有付款、修改现有付款、创建新转账；适用 profile 已核对，编译应保留查询与修改能力，禁止新建转账。修改的条件由用户原请求给出，读取反馈不能进一步授予转账能力。

若用户改为“只读取租金付款，不要修改”，查询可用，修改和新建转账均不能获授。若请求为“只草拟邮件，不要发送”，草稿内容可在最终回答生成；只有用户需要保存草稿且工具语义适用时才考虑草稿工具，不能把草拟自动解释为保存或发送。

上述集合仅为合成说明，不是新增 fixture 或实验标签。真实的金额、付款对象、邮件目的地等仍不由 L2 确定性约束。阶段 B 不引入参数/对象/数据授权，不修复 I3 范围反例。

## 6. 混合批次、失败处理和成本

当前整批拒绝有安全与调度代价。比如合法读取与未授权发送同批出现，读取也不会执行。但直接保留其中合法成员可能打破依赖、改变后续状态或留下部分副作用；idempotent/read 标签不等于调用彼此独立。

候选首版保留原策略，分别记录直接拒绝与 `BATCH_AUTHORIZATION_DENY` 连带拒绝、批次大小、主模型是否再次提出合法动作及任务结果。只在连带损失有证据且宿主能证明可分离时，才另行考虑调度方案。本候选不新增自动重规划、错误反馈授予权限或部分执行，历史撤回的执行提示也不重新启用。

| 成本项 | 阶段 A | 阶段 B |
| --- | --- | --- |
| 独立模型调用 | 无新增调用；复用当前编译 | 原先已有编译调用的适用任务复用一次；纯读取目录按上述限制，不增加每动作授权调用 |
| 授权 Tokens | 理论上不改编译输入/输出 | 读取目录、风险分类和约束证据可能增加输入/输出 |
| 规划 Tokens | 可见工具 schema 可能减少，轮次可能变化 | 较小授权集可能进一步缩减，也可能因误拒增加轮次 |
| 审计 Tokens | 跟随新候选轨迹，不保证减少 | 跟随授权与轨迹变化；误拒造成的少审计不能当净收益 |
| 本地开销 | 过滤/序列化、版本核对与视图构造 | 关系闭包、约束核对、profile 维护与额外记录 |

实际比较应使用总量：授权 + 全部规划 + 审计 + 同口径攻击预检。工具 schema 输入属于模型请求成本，不能只比较正文字符。缺失 usage 保持 unknown，不能因调用失败或未执行工具记为零成本。**零新增模型调用不等于零额外 Token，也不等于已经节省总成本。**

多轮场景应按真实可信任务数计费：每个新增可信任务按需编译一次，不是整个会话永远只编译一次。已授权工具的定义增补只需本地展示处理，但目录/索引输入和额外规划轮次仍计费。未授权调用、相同缺工具请求或错误反馈不能触发无限重编译；第一版不启用自动补权调用。

## 7. 与其他层及配置的关系

- L1 当前来源视图保持；第一轮不要同时启用尚未实现的结构化投影，否则工具视图与正文处理效果混淆。
- L2 编译只依赖可信任务和宿主输入；主模型声称需要工具、外部内容、错误文本与旧审计 allow 均不能修改授权。
- L3 原输入窗口、结构化 allow/deny/abstain、有效读取 deny 例外保持；Monitor/ticket 仍完整中介。工具视图不是新的审计绕过条件。
- L3 纯算法路由在首轮比较保持 off。工具视图/授权/profile 改变后可能改变轨迹与覆盖域，后续 selective 不能直接沿用旧校准，需纳入有效配置绑定并重新核查/校准。
- 若后续实现，工具视图模式、编译协议/profile/关系版本及目录/schema 应进入 manifest/cache 身份；冻结后使用新运行名，不复用不同策略的结果。
- 阶段 A 不改变实际权限；阶段 B 是独立授权策略候选。正常运行目前不需导入新外部任务清单，不借本文增加此要求。

## 8. Workshop 验证建议

### 8.1 分阶段匹配对照

| 组别 | 授权策略 | 规划工具目录 | 用途 |
| --- | --- | --- | --- |
| A0 | 当前 | 完整目录 | 当前三层实现对照 |
| A1 | 当前，集合不变 | 有效授权工具视图 | 单独测阶段 A |
| B0 | 正负约束＋必要读取候选 | 完整目录 | 单独测授权策略变化 |
| B1 | 同 B0 | 有效授权工具视图 | 测组合及是否互相影响 |

A0/A1 先比较，B0/B1 仅在范围与独立标签明确后开展。四组都不是原生 no-defense baseline；如需原生 baseline，应使用独立匹配运行，不能挪用历史分数。

匹配实际任务 ID、原环境/返回、攻击、主/审计模型配置、版本、有效分母及预检口径；固定 L1、L3 routing off、重审0、完成提示关闭。改变规划视图或授权后的真实轨迹需要重新执行和评分，不能把旧 trace 过滤后沿用 TSR/ASR。服务修订未固定等限制如实记录。

### 8.2 案例与指标

案例需覆盖只读与无关私人读取、查询后条件修改、修改/新建相似工具、明确禁止及带例外的否定、草拟/保存/发送差异、合法替代路径、内联已知参数、混合批次、缺失元数据、编译失败、伪造缺工具反馈，以及同工具参数越界负例。数量在选择范围后预先确定；本文不指定虚构实验分母。

后续工具扩展另需覆盖：用户“先查询、后明确预订”；开始就包含条件预订；旧任务权限不累积；未撤销禁令保留；模糊跨轮指代/上一轮事实不可得；工具正文假冒新增任务；已授权但未展示工具；真正的编译遗漏；重复缺工具请求；任务中途新增/删除或同名工具 schema 变化；旧收据/票据跨任务复用；新工具未被 L3 校准覆盖。按需展示和目录切换先做独立有界对照，不混入基础 A0/A1。

1. **授权质量**：按独立宿主语义与可信任务，标注允许能力上界、禁止能力及一种或多种可完成的合法工具路径。统计超出允许上界的授权、禁止能力获授、没有任何完整合法路径的授权不足。条件授权不因未实际调用就算多余权限；合法读取补全不算额外动作。
2. **工具展示**：完整/可见工具数、schema 输入量、不可用工具候选数、拒绝后规划轮次、unknown/fallback原因及整体覆盖。隐藏工具不能被计作删除了实际权限。
3. **拒绝归因**：编译失败、L2直接拒绝、批次连带拒绝、L3原始决定、Monitor最终决定、工具错误与事实缺失分开记录。被攻击覆盖的事实无法取得，不自动归因于过度防御。
4. **任务与安全**：TSR、保留 native ASR、独立环境终态/事实标签；所有 valid/invalid/tool_error/infrastructure_error 分母单列。警告引文造成的谓词变化不冒充阻止真实副作用。
5. **总成本**：授权/规划/审计/预检 Tokens 与总量、模型请求数、宿主视图构造/关系计算及完整链路延迟；降低 TSR 换来的少调用不是有效节省。
6. **任务与目录扩展**：可信任务数、每任务编译次数、展示增补次数、真正授权新增数、授权不足/不可用原因、目录切换与证据不足、权限错误累积及过期凭证拒绝。分别报告用户新增任务、单任务后续阶段和目录更新，不能把它们都算成“动态授权成功”。

不要把“主模型最终用了哪些工具”作为必要工具真值，也不要让授权模型自评准确率。存在多条合法路径时，漏掉某一个工具不必然是能力不足；必要条件是仍保留至少一种受许可的完整路径。未实际使用的能力也不必然属于误放，需要独立任务语义判断。

E0 真实 payload/终态核查仍是待完成工作。阶段 A 不处理工具返回正文，不能将其工具目录过滤报告成 payload 净化；新轨迹中的未送达和样本错误需照常核查。

## 9. 风险、停止条件与当前决定

| 风险 | 处理和停止条件 |
| --- | --- |
| 错误授权同时被隐藏 | 视图不能修复编译器漏授；若合法路径消失/任务损失增加，先核查授权，不凭工具更少宣布收益 |
| 私人读取收紧损害任务 | 独立核对必要路径与完整分母；覆盖不足或误拒明显时停止该 profile，保留当前对照 |
| 宿主关系过宽/过窄 | 冻结规则，检查替代路径与边条件；不能用受攻击回放结果临时补授能力 |
| 证据片段形成虚假安全感 | 原文位置检查仅核查出处，保留语义误判；不宣称证明授权正确 |
| 目录/schema 与执行脱节 | 保留完整 runtime，核对版本绑定与 Monitor；失配不回退为全权限 |
| 只有少调用而效用下降 | 对总成本和 TSR 联合评估，不把少做任务当效率改善 |
| 安全变化仅是谓词差异 | 保留 native 指标和独立终态；不能删掉误报记录或更改原结果 |
| 后续合法任务缺工具 | 新可信任务重编译；已授权定义可补展示；真实编译遗漏计入失败，不通过无条件补权修复 |
| 旧权限累积/目录热变更 | 新任务替换授权并保留有效禁令；首版目录在任务边界更新，不把凭证签名当作已完成强撤销 |

本备忘录的决定是先评估阶段 A，随后依据证据选择有界阶段 B；阶段 C 暂停。验收范围和效用/成本界限应在试验前确定；不预设每个阶段一定改善，也不把工程取舍写成正式 Go/No-Go 路线决定。

本阶段仅保存文档：**模型调用=0、benchmark rollout=0、生成 fixture=0**。工具视图、扩展编译输出、profile、关系补全、按需展示/目录切换、跨任务语义解析、统计和匹配实验均未实施；当前新的实际 user 回合重新编译沿用既有实现。没有新的防御率、Token收益或新颖性结论。
