# Dashboard 使用指南

在 `DSCG/` 且 `ipi` 已激活时运行：

```bash
python -m dashboard.app
```

默认地址为 [实验配置](http://127.0.0.1:8888/)；[历史分析](http://127.0.0.1:8888/history)是并列页面。可用 `PORT` 覆盖端口。用户从面板启动的实验保存到 `results/dashboard/`。

## 防御结构

实验页顶部“防御架构”展示当前已实施的 three-layer-v1：L1 工具返回隔离、L2 可信任务工具授权与候选前置检查、L3 当前动作语义审计；Monitor 与一次性票据单列为执行基础设施。L2 在首次候选前编译，工具结果通过 L1 进入主模型，后续候选先检查 L2 再路由 L3。

该图描述完整防御的默认配置。页面原两个开关控制 L2/L3，关闭任一属于消融；保留任一防御时 L1 默认启用，两者全关时 L1 也关闭。原生 baseline 仍不经过 DSCG。审计重试为 0，完成提示关闭；L3 学习免审和授权对照校准尚未实施。

非法混合批次整体拒绝，不执行其合法成员；Monitor 重新检查前置结果与当前授权/目录。L1 不增加模型调用，但会增加历史输入；实际总成本与 ASR/TSR 改善尚无模型实验。当前约束仍是工具级，对象、目的地、参数与数据权限未强制约束。新运行应使用新名称，历史页面保留旧版本结果。

## 历史对比

1. 选择实际结果目录，例如 `partial_benchmark/` 或 `benchmarks/`。
2. 多选模型/运行名称，如 baseline 与优化版本；清空选择时不会自动恢复全选。
3. 选择同一攻击和场景，核对任务 ID、模型配置与计分口径。
4. 在结果列表勾选需要比较的运行，再生成图表或下载分析数据。

更新筛选默认勾选全部匹配结果；自动刷新保留手动排除项。分析与导出只使用当前可见且勾选的结果。

同一模型/运行名称在列表、图表和明细中共用颜色与字母标记；多攻击对比另用攻击编号、点形和线型。顶部图例突出版本名，完整身份保留在提示和导出中。TSR、ASR 分图展示，Token 使用独立尺度；超过 6 个对比项时图表改为单列，窄屏纵向排列。颜色与标记在同次加载中保持一致，不跨重新加载持久化。

支持新 `<model>_<name>/<attack>/<suite>/` 与旧目录结构，不迁移原始数据。攻击缺失显示“未记录攻击”，旧混合汇总显示“混合攻击”；筛选攻击相同不等于任务 ID 相同。

## 下载分析数据

点击“下载分析数据”即可获取 ZIP，无需先画图；下载始终同时包含 ASR 与 TSR。

| 文件 | 内容 |
| --- | --- |
| `analysis.json` | 结构化分析入口：来源身份、指标、逐任务 outcome、分子/分母及缺失/截断告警 |
| `summary.csv` | 实验与场景指标对比 |
| `task_records.csv` | 按任务 ID、模型、攻击对齐的明细 |
| `README.md` | 指标口径和限制 |

百分比为 0–100；缺失值为空。明确报错的明细不计入观察性 ASR/TSR 分母，旧记录可能为 unknown。原汇总和明细统计分开保存；每次最多导出 50,000 条明细，并标明截断。导出不含完整工具轨迹，也不能独立证明 E0 通过或框架有因果增益。

历史实现验收见[归档索引](../workshop/archive/project_structure_20261008/README.md)；当前对应源码在 [dashboard/](../dashboard/)。
