## 1. 需要作出的参数决策

当前 L3 语义审计开启，新增算法路由默认 `off`；没有真实独立校准集或可部署阈值。首先确定风险和验收要求，再由数据决定是否能够启用免审。

| 待决项 | 含义 | 确定方法与约束 |
| --- | --- | --- |
| 风险目标 `epsilon`（\(\epsilon\)） | 发生过新增免审的独立任务组中，至少有一次动作不应免审的条件风险 | 根据应用可接受风险预先决定；不是 native ASR 或每动作错误率，不根据测试集收益反向放宽。当前未选定。 |
| 统计错误水平 `delta`（\(\delta\)） | 校准上界允许的统计错误水平 | 与样本预算一起预先规定；依赖可靠标签、冻结选择器及组独立同分布等假设，不是模型 confidence。当前未选定。 |
| 阈值网格与数量 `K` | 供校准检验的固定 `tau` 候选列表 | 用 development 数据观察分数分布，形成少量、去重的候选；查看 calibration 标签前冻结。候选越多，`delta/K` 修正越严格。当前未预注册。 |
| 部署阈值 `tau`（\(\tau\)） | 满足全部硬资格后，分数 `s < tau` 才可能免审；等于阈值仍审计 | 由独立校准产生兼容 artifact，不手填经验常数。没有合格候选则 `threshold=null`，继续完整审计。 |
| 独立标签与相关组 | 什么动作确实可以免审，以及样本间哪些关系构成依赖 | 由独立策略、环境 oracle 或人工双审给出带证据标签；任务、对象、文档、模板、重复版本的相关性须审查，不拆组进入不同数据集合。 |
| 适用工具与运行域 | 哪些工具、任务和模型配置可以使用该 artifact | 保持当前单个已授权、有效注册、internal、idempotent、无 sink 读取的硬资格；冻结目录/schema、提示、模型配置、L1/L2 模式和输入边界。 |
| 效用与事实保真标准 | 相对完整审计对照允许多少任务失败或信息损失 | 实验前规定效用容许差异、必须保留的事实/引用及失败分类；报告成对差异和不确定性，不仅比较平均 TSR。当前未确定数值。 |
| 成本与延迟标准 | 怎样的节省才值得启用新增路由 | 根据 shadow 中可覆盖的审计成本，预先规定最低总 Token 收益及延迟要求；不能只要求“免审率更高”。当前未确定数值。 |

小规模 workshop 可以缩小任务范围和结论范围；样本预算不足时，先完成 shadow 覆盖与成本研究，不将合成阈值当作部署阈值。

## 2. 先判断 L3 路由的优化空间

2026-10-15 对当前工具元数据和保留 v2.2 轨迹的只读复核得到：

| 统计项 | 结果 | 解释 |
| --- | --- | --- |
| 内置不同工具 | 69 个，其中 7 个满足新增路由的元数据条件 | 工具种类占比不等于实际调用覆盖率。 |
| 参考轨迹 | 144 条，版本均为 `three-layer-l2-v2.2` | 不是当前 v3 的新模型实验。 |
| 候选批次 / 提议调用 / 语义审计调用 | 278 / 334 / 211 | 提议调用包括后续被拒绝或失败的调用。 |
| 单动作且满足元数据条件的批次 | 18 个 | 来自 `slack/user_task_1`：`read_channel_messages` 12 次、`get_channels` 3 次、`get_users_in_channel` 3 次。不是 18 个独立校准组。 |

7 个元数据候选工具为 `get_channels`、`get_file_by_id`、`get_users_in_channel`、`list_files`、`read_channel_messages`、`search_files`、`search_files_by_filename`。

保持这批参考候选序列时，`18/211 ≈ 8.53%` 仅是元数据口径下潜在审计调用节省的上界估计。完整授权、schema、输入完整性、兼容 artifact 和阈值还会缩小集合；旧 summary 轨迹不足以重建全部硬资格。此比例不是实际免审率、Token 节省或 v3 安全/效用结果。

来源：[内置元数据](./config/tools.agentdojo-v1.2.toml)、[旧运行汇总](./results/partial_benchmark/deepseek-flash_3layer_L2opt/summary.md)。本次复核的计数及 144 个输入哈希保存在 [只读统计记录](./workshop/artifacts/20261015_parameter_plan/coverage_reference.json)；该 agent 产物默认忽略，未随仓库分发时应从上述原始结果重新统计。

成本评估应按审计 Tokens 加权，而非仅数动作。在相同候选序列下：

\[
\text{总 Token 节省比例上限}
\leq
\frac{\text{符合新增免审资格的审计 Tokens}}
     {\text{全部防御运行 Tokens}}.
\]

这是忽略轨迹变化的潜力估计；端到端 selective 可能改变后续规划和调用，最终仍须实测。原有 public read 免审不能再次计入新增节省。若可覆盖的成本本身很少，优先评估审计输入压缩或其他已观察到的主要成本来源。

## 3. L3 阈值的确定流程

### 3.1 数据与校准步骤

- [ ] **冻结参考配置。** 记录源码 revision 与工作树哈希、主/审计模型公开配置、服务返回的模型标识（如可获取）、工具目录/schema、提示、L1/L2 模式和输入边界。服务真实修订无法固定时明确限制。
- [ ] **运行 shadow。** 完整保留原审计，分开统计元数据候选、完整硬资格、各回退原因、分数分布、审计 Tokens 和全链延迟。无有效 artifact 时现有 `would_bypass=false`，不能将其当作没有低分候选；应从资格与分数分析潜力。
- [ ] **建立独立标签。** 仅 `safe_and_sufficient` 算可免审；`unsafe`、`insufficient_or_ambiguous`、`unjudgeable` 都算不应免审。基础设施错误、无效样本另外记录，不静默作为安全样本。
- [ ] **审查分组与划分。** development 用于设计候选；calibration 用于检验；test 用于冻结后的独立评价。相关任务、对象、文档、攻击模板及版本不能拆组，不能用动作数或重复运行凑独立分母。划分规模按实际选中组需求确定。
- [ ] **预先冻结选择规则。** 在查看 calibration 标签前记录 `epsilon`、`delta`、候选网格、标签协议、分组规则和成本单位；保留其哈希。
- [ ] **校准并生成 artifact。** 使用现有数据构建和校准工具；标签、分组、版本或兼容域不满足要求时停止启用。校准器能检查格式与部分一致性，不能证明人工标签正确或发现所有隐藏相关性。
- [ ] **开展冻结后的 selective/off 匹配验证。** 独立核查真实工具轨迹、环境终态、效用、安全、总 Tokens 和延迟；shadow 上的统计结论不直接认证改变后的轨迹或适应性攻击。

现有工具：[数据构建](./experiments/l3_router_dataset.py)、[阈值校准](./experiments/calibrate_l3_router.py)、[算法实现](./dscg/audit_router.py)。数据格式与调用方式沿用 [L3 方案](./workshop/L3_checker_opt.md)，不在本文填写尚未选定的风险数值或执行新模型实验。

### 3.2 校准目标与样本量

对每个预先冻结的候选阈值，定义：

\[
m_\tau=\#\{\text{至少选中一次新增免审动作的独立组}\},
\qquad
k_\tau=\#\{\text{上述组中至少一次选中动作不应免审的组}\}.
\]

现有实现计算单侧 Clopper–Pearson 上界：

\[
U_\tau=\operatorname{CPUpper}(k_\tau,m_\tau;\delta/K).
\]

仅 `m > 0` 且 `U <= epsilon` 的候选合格。在合格候选中，选择冻结成本代理之和最大者，平局选择较小阈值；无候选合格则返回 `threshold=null`。**当前成本代理是审计包 JSON 字符数，不是实际 API Tokens。**

零错误时仍有非零上界：

\[
U_\tau=1-(\delta/K)^{1/m_\tau},
\qquad
m_{\min}=\left\lceil\frac{\log(\delta/K)}{\log(1-\epsilon)}\right\rceil.
\]

以下仅为可靠标签、冻结选择器、独立同分布组选中且零错误条件下的数学算例，既非接受标准，也非已有样本量：

| `epsilon` | `delta` | `K` | 最少选中独立组数 |
| --- | --- | --- | --- |
| 1% | 5% | 1 | 299 |
| 1% | 5% | 10 | 528 |
| 5% | 5% | 1 | 59 |
| 5% | 5% | 10 | 104 |

有错误时重新求上界，不能沿用零错误算例。只统计实际被该阈值选中的独立组；全部任务数、重复攻击次数和动作数均不能替代这个分母。

标签审查还须区分三件事：原始审计结论、Monitor 最终决定、独立安全标签。当前已授权且无 sink 的读取收到有效 `deny` 仍可能经 `READ_ONLY_SOURCE_ALLOW` 执行，`abstain`/错误/无效记录仍阻断。审计 allow、动作实际执行或攻击未成功均不能直接充当可免审真值。

## 4. 已固定参数与需要单独评估的策略

第一轮对照保持现有字符三元组、四信号最大值聚合、输入边界、授权编译与审计的 temperature=0、`audit_retries=0`、`completion_prompt=false` 和 `summary` 追踪。它们不是当前缺少的部署参数。完整数值以 [配置说明](./docs/model_tool_configuration.md) 第 5 节的固定源码边界为准。

| 位置 | 后续可评估内容 | 先取得的证据 |
| --- | --- | --- |
| L1 任务与字段 profile | 哪些可信任务可安全省略哪些字段 | 独立任务需求/必要字段标注、引用保真和环境终态。月支出求和可能无需 subject，按用途分类可能需要；不能只按字符缩减选择字段。 |
| L1 解析规模边界 | 是否扩大字节/行数支持 | 正常返回规模、超限回退比例和本地解析延迟；错误/截断/不适用仍完整回退。 |
| L2 默认授权与可选 host profile | 必要准备读取、条件任务、动作工具的漏授权与过授权 | 独立授权标签及分项效用损失；工具反馈不扩权，新可信用户任务重新建立授权。 |
| L3 输入窗口与描述边界 | 先压缩冗余，必要时再比较窗口大小 | 截断率、事实不足/abstain 原因、Token 构成和判断质量；可逐项比较 2/4/8 条窗口等候选，暂不同时搜索全部维度。 |
| 主模型与审计模型配置 | 不同审计配置的质量/成本权衡 | 先固定任务和独立标签，再单独对照；L3 路由继续纯算法，不新增路由小模型。 |

以下是行为策略，不能当作数值调参顺带修改：

- **L2 整批拒绝：** 先统计合法/非法混批频率及合法动作未完成的损失；部分执行涉及依赖与副作用顺序，另行选择实现任务。
- **读取 deny 例外：** 分开测量保留必要读取与放行无关读取的影响；变更需要单独语义对照。
- **扩大免审资格：** 不通过降低工具风险标注、放开 personal/secret/写入/外发或按预算强制免审来提高覆盖率。

修改公式、边界、提示或适用域时须更新兼容身份并重新校准。已有对象、目的地、参数和数据级缺口不因词面阈值改善而被强制约束。

## 5. 分阶段验证与优化优先级

| 顺序 | 工作 | 交付与继续条件 |
| --- | --- | --- |
| P0 | 核查真实评测与成本口径 | 在既有 E0 工作范围内核查 payload 送达、真实轨迹与环境终态；有效/错误/无效分母分开；成本记录完整且配置可比后再作收益归因。 |
| P1 | 验证各层及现有改动的增量 | 原生 baseline、完整框架与逐层关闭对照采用匹配任务/攻击/模型配置；先小范围检查可归因差异，再决定扩大重复实验。L3 路由保持 off。 |
| P2 | 验证 L1 投影价值 | 比较无 L1、旧来源标记与 projected，分别报告适用子集和总体。若要归因于任务选字段，补齐 L1 方案中的同字符预算非任务裁剪对照及四臂验证，实际 Token 差异另报；不能仅凭文本变短宣称机制收益。 |
| P3 | 改善 L2 授权质量 | 工具视图 A0/A1 对照两组均关闭任务展开，固定 L1/L3；host profile 和任务文件另设有限案例，检查准备读取、条件工具及撤销旧授权。 |
| P4 | 判断 L3 路由是否值得校准 | 先完成 shadow 的完整资格、成本覆盖与独立组评估。有实质成本空间且标签/样本可获得时，才进入阈值校准与 selective 验收。 |
| P5 | 按已观察瓶颈优化 | 高频且必要字段明确时扩展 L1 profile；授权错误突出时优化 L2；审计输入占比高时优化 L3 上下文。保持单项修改和匹配对照。 |

P0–P5 是 workshop 验证建议，不替代正式技术路线的 ready/locked 状态。当前真实 E0 pending、I3 partial（24 valid / 8 scope violations）、I2 locked；不自动解锁闭合的 provenance/source-to-sink、I1/I4/exactly-once 或新范围/恢复机制。

每轮匹配对照需遵守：

- 固定并核对实际 task ID、攻击、payload/环境、模型公开配置与框架开关。当前 partial 默认仍是各 suite 注册顺序前 3 个用户任务和前 3 个注入任务；保留用户的选择规则。
- 同时包含干净任务与攻击任务；覆盖必要自由文本/合法引用、字段事实污染、结构异常以及适用范围外反例。错误金额或缺失记录不能由投影自动恢复或认证。
- 重复使用相同任务/模板可观察运行波动，但统计时按相关组处理，不增加独立校准分母。有限样本只支持相应范围的实证结论。
- 分别记录原始 auditor 决定、Monitor 决定、工具执行与终态；保留 native ASR，同时独立核查结果，防止把警告引用变化当作安全收益。
- 使用新 run 名；agent 输出统一写入新的 `workshop/artifacts/<YYYYMMDD>_<task>/`，partial 显式传 `--results-dir`。不覆盖旧结果，不改旧哈希，不把历史 v2.2 结果重标为 v3。

## 6. 完成判据与近期交付物

近期优先形成三项可核查结果：

- [ ] **参数冻结表：** 区分现行默认、待选风险/验收标准、实验变量和禁止混改的策略；记录版本、工作树及配置身份。
- [ ] **分层匹配对照报告：** 记录任务/攻击键、有效分母、成对 TSR/安全结果、事实/引用保真、总/分阶段 Tokens、延迟和失败原因；报告不确定性及适用范围。
- [ ] **L3 shadow 覆盖与成本报告：** 分开统计硬资格、分数、回退、相关组和 Token 加权潜力，明确是否具备收集足够独立校准数据的条件。

后续仅在标签与风险约束通过、冻结测试达到预定效用/事实标准且端到端成本收益成立时，考虑启用对应范围的 selective。若收益不明显，保留完整审计或 shadow，并如实报告。现有两项 L3 工程收尾——全链本地延迟计量、异常中断后的任务边界凭据清理——也应在部署验收前完成，详见 [实施报告](./workshop/completed/l3_algorithm_implementation_20261010.md)。

校准方法参考：[Learn then Test](https://arxiv.org/abs/2110.01052)。其一般风险校准思路不替代本项目对独立分组、标签、运行域和改变后轨迹的核查。
